# FAQ Capture（对话 → 结构化工地沉淀）

把当前对话蒸馏成可复用的 FAQ 条目，写入 `FAQ/YYYY-MM-DD.md`。核心原则：**蒸馏而非转录**——提取问答、决策与纠正，不复制聊天记录。

产物随仓库分发：别人拉取本仓库后遇到问题，先查 `FAQ/` 是否有已有解决方案。

---

## Step 0: 清晰度门控（先判断，再决定问不问）

检查当前对话是否满足**全部**条件：

1. **主题单一**：对话围绕一个可一句话命名的主题，没有明显跑题分支
2. **术语一致**：关键概念没有歧义或一词多义
3. **素材可提取**：能识别出 ≥3 组「问题 → 答案/决策」内容
4. **输出去向明确**：知道写到哪、给谁看

- 全部满足 → **跳过提问，直接进入 Step 2**
- 任意一条不满足（典型信号：上下文主题分散、多话题混杂、无法一句话概括「这份 FAQ 讲什么」）→ 进入 Step 1

## Step 1: Grilling（需求不清晰时的收敛追问）

目标是收敛 FAQ 范围，**每轮只问当前已解锁的问题**，一轮内全部列出并编号：

- 每个问题给出**推荐答案**（➡️ 标注），用户确认或修改
- **事实自己查，决策问用户**：能从对话记录/文件/工具里查到的信息不要问用户
- 收敛目标（通常 1 轮，最多 2 轮）：
  - Q1 主题与范围：这份 FAQ 只讲什么、明确不讲什么
  - Q2 受众：给未来的自己，还是给团队新人
  - Q3 核心内容点：必须覆盖的 3-5 个要点
  - Q4 输出：确认写入 `FAQ/` 当日文档
- **边聊边沉淀**：每敲定一个要点就先写进草稿骨架，不要最后一次性回忆；术语有歧义当场敲定唯一命名
- 用户确认达成共识后进入 Step 2

## Step 2: 生成与去重写入

**条目模板**（蒸馏而非转录）：

```markdown
## Q: <问题标题>

> 规范化 key：<小写去标点去空白后的问题>

<≤3 句的精炼回答；必要时附来源链接>
```

规则：
- 只写对话中真实出现的内容，禁止编造；外部引用附链接
- 每个回答 ≤3 句；超出就拆成多个 Q，或归入「待定问题」
- 语言跟随对话语言（技术术语与代码标识符保留原文）
- 完成后向用户报告文件路径，并列出**主动省略**了什么（噪声过滤说明）

**写入前置：两步去重**（顺序执行，一条链）：

1. **确定性查重（零 LLM）**：把问题标题规范化（小写 → 去标点 → 去空白）得到 `normalized_key`，查 `FAQ/_索引.json` 的 `records`。
   - 命中 → 已有条目 → 进入「命中处置」分支
2. **LLM 语义查重（模糊相似）**：规范化 key 未命中时，把「新问题 + 索引里全部已有问题标题」**一次性**交给 LLM，问是否同一问题（只调一次，不逐条查）。
   - 判定重复 → 进入「命中处置」分支
   - 判定新问题 → 写入当日文档 + 更新索引（见下）

**命中处置分支**（已有答案存在时，不得直接新增）：

| 情况 | 处置 |
|---|---|
| **同一问题 + 零增量**（纯换措辞） | 不新增；报告已有答案位置（文件+条目），问用户「跳过 or 更新」 |
| **同一问题 + 新角度**（跨日期补充，如 9-20 记录、9-22 新角度） | **并回原始日期文件**（不写当天文件），新角度前加日期标记（见下），更新索引 `updated_at` |
| **不同问题（同主题不同角度）** | 新增条目到当天文件，放同一主题分节，条目间互加引用链接 |

**新角度并入旧条目的格式**（示例）：

```markdown
## Q: Windows 上 Python 不在 PATH 怎么办？
> 规范化 key：windows上python不在path怎么办

用 `py` 启动器（3.12.6）……（原始答案）

> **（9月22日新添）** pip 也装不上时：先检查 `pip` 是否在 `Scripts` 目录下，加入 PATH 后重开终端。
> 来源：9月22日对话
```

**索引更新**（`FAQ/_索引.json`，与 `_收藏索引.json` 同构）：

```json
{
  "version": 1,
  "updated_at": "2026-09-22T09:00:00",
  "records": {
    "windows上python不在path怎么办": {
      "question": "Windows 上 Python 不在 PATH 怎么办？",
      "file": "2026-09-20.md",
      "added_at": "2026-09-20",
      "updated_at": "2026-09-22"
    }
  }
}
```

- 新条目：`added_at` = 当天；`updated_at` 同步当天
- 合并新角度：`file` 保持原始文件不变，`updated_at` = 新角度当天
- **漂移防护**：追加时若发现索引里某个 key 指向的文件/条目已不存在（如手工删改），自动重建索引（扫描 `FAQ/` 下所有 md 的 `## Q:` 标题重建），不手工修
- 待定问题（见下）**不进索引**，不参与去重

## 目录与文档结构

```
FAQ/
├── 2026-09-20.md      ← 按日期一个文档
├── 2026-09-22.md
└── _索引.json          ← 全局去重索引
```

单日文档结构：

```markdown
---
日期: 2026-09-20
条目数: 3
---
# FAQ · 2026-09-20

## 部署与配置
## Q: ...

## 数据与抓取
## Q: ...

## 待定问题
- <对话中提出但尚未解决的问题>
```

## 反模式

| 借口 | 现实 |
| --- | --- |
| 「把聊天记录整理一下就行」 | 那是转录。FAQ 要提取问答与决策 |
| 「主题有点散，但先写吧」 | 散就要先 grill，否则产出是垃圾 |
| 「这个问题我可以猜答案」 | 有推荐答案也要问；FAQ 定稿后错误会固化 |
| 「一次抛 10 个问题」 | 只问当前轮已解锁的；依赖问题留下一轮 |
| 「先攒着最后统一写」 | 要点敲定即写入草稿，避免回忆失真 |
| 「问题换个说法，直接再写一条」 | 先走两步去重；零增量的措辞变体不新增条目 |
